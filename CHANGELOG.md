# Changelog

All notable changes to sandtable are documented in this file: the `sandtable-ai` CLI and library on npm, its Python launcher on PyPI, and the Claude Code plugin in this repository, which share one version number.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0, a minor release may change the domain spec, the CLI or the library API; every such change is marked **Breaking:** and says what to do.

## [Unreleased]

First public release.

### Added

- **Engine**:
  - domain spec: world tables, tools as atomic ops with checks and defaults, invariants, personas and tasks with hidden goals
  - simulated user ↔ agent episodes on a fresh world per trial. The simulated caller follows its task's instructions over its persona, says only what a customer would say aloud, asks for nothing its goal doesn't mention, and hangs up once it is transferred ([#85](https://github.com/sandtable-ai/sandtable/issues/85))
- **Grading**:
  - deterministic: end state, invariants on every tool call (`before`, `require`, `limit`, `match`, `never`), `never_disclose` on agent messages, required and forbidden tools
  - `never_disclose.unless` takes one exception or a list of them. The freight example uses a list so that a rep-confirm offer agreed at exactly `max_rate` can be read back and submitted, as the booked rate already could ([#86](https://github.com/sandtable-ai/sandtable/issues/86))
  - a YAML number matches a string with the same digits (`100101` and `"100101"`); zero-padded IDs such as `"007"` still differ from `7`
  - pass^k, failure-mode clustering, per-tag scores
  - soft invariants: `soft: true` on any invariant kind checks it as usual, but breaking it never fails a trial. `results.json`, the terminal summary, the HTML report and the leaderboard report how often each was broken, out of the trials where it applied. `limit` also takes strict bounds, `lt` and `gt`. The freight example's soft `counter-at-ceiling` reports how often counter-offers reach the price ceiling, which the policy allows ([#120](https://github.com/sandtable-ai/sandtable/issues/120))
- **`sandtable init`**: drafts a domain from an OpenAPI spec (deterministic), an SOP (invariants that quote their source) and call transcripts (tasks, personas and fictional seed rows, PII scrubbed locally). Everything stays `review: pending` until accepted.
- **`sandtable lint`**: proves each task is ready, solvable (reference replay), non-vacuous and graded, without model calls.
- **`sandtable regrade`**: re-scores a past run's stored trials after you edit an invariant, an expectation or a `never_disclose` rule, without calling a model, so a fixed grading rule doesn't cost a rerun. It replays each trial's tool calls against a fresh world and grades the conversation as a live run would. It refuses when a replayed call returns something other than what the agent saw, or when the agent or the caller would be given something else now (the policy, a tool's schema, or a task's caller prompt, opening or turn limit), which `results.json` records as an `inputs` hash. The library exports `regradeSuite`, `regradeTrial` and `RegradeError` ([#32](https://github.com/sandtable-ai/sandtable/issues/32)).
- **`sandtable leaderboard`**: ranks several agents on one domain under the same simulated callers, next to a do-nothing baseline, by pass^k with rule violations, cost per trial and p95 turn latency. It writes `leaderboard.json`, `LEADERBOARD.md` and `leaderboard.html`, and resumes an interrupted run without paying for finished models again. A model's stored conversations are reused only for the same agent spec, domain, k, caller and tasks with no crashed trial, and are always graded again under the current rules; otherwise it reruns and says why. `-t` limits every model and the baseline to some tasks. A model whose trials crashed shows as an error instead of a 0% score. Cost / trial counts the agent's model only, and a `noop` entry is skipped in favour of the built-in baseline ([#93](https://github.com/sandtable-ai/sandtable/issues/93)).
- **Leaderboard config**: `leaderboard/models.yaml` lists the 14 models the freight leaderboard runs, with its simulated caller, k=4, the rule that picked them and the models left out. Its Claude models and the caller run on global inference profiles, like the other models that have one. It replaces `leaderboard/models.example.yaml`, and a test checks that every model on it, and the caller, has a price in `prices/bedrock.eu-west-1.json` or the built-in Claude prices ([#150](https://github.com/sandtable-ai/sandtable/issues/150)).
- **Leaderboard provenance**: each model's `run.json` records the sandtable version and the git commit its trials ran from (with `dirty` for uncommitted changes, recorded only from sandtable's own clone), the provider when a Claude model ran, and the AWS region when anything ran on Bedrock. Without `--region` or `AWS_REGION`, the leaderboard takes the region from the AWS profile's config and sends every Bedrock call there, Claude's included. `leaderboard.json` records the sandtable that ranked it, and `LEADERBOARD.md` names its version and commit. A run from a checkout with uncommitted changes prints a warning ([#152](https://github.com/sandtable-ai/sandtable/issues/152)).
- **Adapters**:
  - Claude on the Anthropic API or Amazon Bedrock (`--provider bedrock`), with prompt caching
  - any tool-capable model on Amazon Bedrock through the Converse API, such as GPT, gpt-oss, Grok, Kimi, Qwen, Mistral or Nova: `--agent bedrock:<model-id>`. On Claude and Nova models it caches the tools, the system prompt and the conversation up to the newest message it may mark, so each call pays the cache rate for context it already sent. Other models get no cache points, because Bedrock rejects the request for them, and neither do Claude models older than Claude 3.5 Haiku, which don't support prompt caching ([#141](https://github.com/sandtable-ai/sandtable/issues/141))
  - any model behind an OpenAI-compatible Chat Completions endpoint (OpenAI, OpenRouter, LiteLLM, vLLM, Ollama, Groq, Together), as agent or simulated user: `--agent openai:<model>`, `--user openai:<model>`
  - HTTP step protocol, keyed by a `session_id` of `<run-id>/<task-id>#<trial>` that no other run reuses; JS/TS module agents; `noop` baseline; scripted user
  - the Claude, Bedrock and OpenAI-compatible adapters retry rate limits, server errors and network errors with backoff, so a long run doesn't lose trials to throttling
- **Reports**:
  - terminal summary, `results.json` (with the run's `runId`), and a self-contained HTML report with transcripts, tokens, estimated cost and turn latency. Each line of the summary's top failure modes fits an 80-column terminal: it names the first tasks that hit the failure and counts the rest (`… +24 more`), and long examples end in `…`. The full lists stay in `results.json` and the report ([#79](https://github.com/sandtable-ai/sandtable/issues/79))
  - `--fail-under` CI gate; `run --open` opens the report
  - `--prices <file>` adds verified prices for models sandtable doesn't price itself; `scripts/bedrock-prices.mjs` resolves Bedrock prices from the AWS Pricing API
  - the HTML report's trial view shows rule ids in their own case on the tool call that broke them, hangs each check's detail under its rule id, and wraps long tool arguments, results and record changes between fields instead of running past the card ([#70](https://github.com/sandtable-ai/sandtable/issues/70))
- **Claude Code plugin**: this repository is a plugin marketplace (`/plugin marketplace add sandtable-ai/sandtable`). Its skills teach a coding agent to draft and review a domain, write tasks, run it and attribute failures; a `failure-triager` subagent reads failing trials. Not part of the npm package.
- **Python launcher**: `uvx sandtable-ai` or `pip install sandtable-ai` installs a `sandtable` command that runs the matching CLI release (Node.js 20+ required).
- **Examples**:
  - a fictional freight carrier-sales desk with 50 tasks (32 that must write, 18 that must not) and 18 invariants, one of them soft. It covers vetting, search by lane, pickup window and equipment, multi-round negotiation with every counter-offer logged, offers a human rep confirms, capacity logging, callbacks and handoffs. `sandtable demo` rehearses it offline and opens the failing report. In the multi-round negotiation tasks the caller's floor is stated apart from its asking prices, so a simulated caller no longer turns down offers it should accept ([#87](https://github.com/sandtable-ai/sandtable/issues/87)).
  - a hard tier of 18 freight calls, tagged `hard`: longer calls (two or three trucks, a rep-confirm load next to an instant one, a callback next to a booking, an MC number or date the caller corrects), details to check (weight limits, rates quoted as linehaul plus fuel, the best-paying fit on a busy lane, a conditional yes) and callers who test the rules (an outside dispatcher, a sister company's MC, double brokering, another load's ceiling, a broker claiming its own trucks). `policy.md` states every rule they rely on, and the offline careful agent passes all of them while the naive and noop agents pass none ([#121](https://github.com/sandtable-ai/sandtable/issues/121)).
  - a fictional clinic front desk with 25 tasks and 12 invariants, and offline careful and naive agents (`--agent scripted:clinic-careful`)
  - worked examples that rehearse agents built with the Vercel AI SDK, the OpenAI Agents SDK, the Claude Agent SDK, Pipecat, LiveKit Agents and a plain HTTP service, each a one-file adapter checked offline in CI, with a guide (`docs/guides/frameworks.mdx`) ([#52](https://github.com/sandtable-ai/sandtable/issues/52))
- **Docs** at [sandtable.dev](https://sandtable.dev), with `llms.txt` for coding agents: concepts, guides, a reference for the CLI, the domain spec, the HTTP step protocol and `results.json`, and comparisons with τ-bench, LangWatch Scenario, IntellAgent and hosted platforms, each claim linked to the tool's own docs ([#54](https://github.com/sandtable-ai/sandtable/issues/54)), and a guide to the Claude Code plugin: installing it, its skills and subagent, and a worked session ([#72](https://github.com/sandtable-ai/sandtable/issues/72)).
- The published CLI runs on Node.js 20 or later.

### Fixed

- `examples/freight`: the policy says a company name matches the MC record when only a suffix such as Co, Inc or LLC differs. Callers say "Tumbleweed Freight" for "Tumbleweed Freight Co", and an agent that read the rule strictly transferred the call and failed a task that expects the booking ([#161](https://github.com/sandtable-ai/sandtable/issues/161)).
- `examples/freight`: three hard-tier callers can no longer make their task easier. `caller-corrects-mc-and-date` opens with a fixed line that gives the first pickup date, so the date the caller later corrects is always said. The caller in `busy-lane-best-fit` never says which loads fit or picks one the agent hasn't recommended, and the caller in `sister-company-mc` never asks to be transferred ([#162](https://github.com/sandtable-ai/sandtable/issues/162)).
- **Adapters**: `--agent bedrock:<model-id>` allows 16,000 output tokens per model call, the same as the Claude adapter, instead of 4,096. Reasoning counts against the limit, so a reasoning model such as GPT-6, Kimi K3 or gpt-oss could be cut off mid-reply or before its tool call, and the cut-off looked like a short reply ([#154](https://github.com/sandtable-ai/sandtable/issues/154)).
- `examples/freight`: a trial fails when the agent reads out the id of an offer it submitted for a rep (`submitted_offers-1`) as a confirmation or reference number. The policy says a rep-confirm load gets no confirmation number, and before this nothing graded it. The new invariant is `never-disclose-submission-id` ([#117](https://github.com/sandtable-ai/sandtable/issues/117)).
- `examples/freight`: the policy says today's date (Monday, November 2, 2026, 9:00 a.m.), as the clinic's does. Callers give dates without a year, and an agent that had to guess the year from its training cutoff could search for pickups in 2023 and find nothing. Two callers whose insurance renews on a Monday now say "next Monday", which no longer reads as today ([#146](https://github.com/sandtable-ai/sandtable/issues/146)).
- `prices/bedrock.eu-west-1.json` prices GPT-6 Astra, GPT-6.1 Sol and GPT-6 Luna, so a leaderboard run with it shows their cost instead of `n/a`, and covers every Bedrock model in the launch leaderboard. The AWS Pricing API doesn't list them; their prices come from AWS's model cards (Global CRIS, Standard, short context) and are kept with each source in `prices/bedrock.verified.json`, which `scripts/bedrock-prices.mjs --verified` reads. Claude Sonnet 5.5 cache reads cost $0.10 per million tokens, not $0.20, after the October 7, 2026 price cut ([#148](https://github.com/sandtable-ai/sandtable/issues/148)).
- **Grading**: `never_disclose` follows the order of the conversation. An `unless` call allows its value only from the agent turn it was made in, so "the max we can do is $2,715" fails even if the agent books $2,715 later, and a value the caller said before the agent did is not a leak when the agent repeats it. Re-graded with this rule, ten passing trials of the cross-vendor freight runs fail, each a ceiling called a max ([#136](https://github.com/sandtable-ai/sandtable/issues/136)).
- `scripts/bedrock-prices.mjs` matches a model ID to usage types spelled differently, so Nova 2 Lite (`global.amazon.nova-2-lite-v1:0`, priced as `Nova2.0Lite`) resolves, and `prices/bedrock.eu-west-1.json` now prices it: a leaderboard run with that file shows its cost instead of `n/a`. Usage types marked `-cross-region-global` count as global. A model ID never takes the price of a longer name or another version (`grok-4` is not `grok-4.6`). Each model the script can't price is listed under `unresolved` with the reason, such as no eu-west-1 usage type naming GPT-5.5 ([#137](https://github.com/sandtable-ai/sandtable/issues/137)).
- **Grading**: `never_disclose` and `reply_includes` read the Unicode hyphens U+2010 and U+2011 as `-`. gpt-oss types IDs as `L‑1015`, which failed the freight example's `never-disclose-ceiling` because another load's `max_rate` is 1015, while a phone number or date of birth typed as `555‑0148` slipped past `never_disclose`. En and em dashes still end a number ([#132](https://github.com/sandtable-ai/sandtable/issues/132)).
- **Adapters**: `--agent bedrock:<model-id>` no longer passes reasoning that a model writes into its text on to the caller and the graders. gpt-oss sometimes sends its reasoning as `<reasoning>…</reasoning>` in the text instead of in a reasoning block, and one such reply named a load's `max_rate`. Closed spans are dropped from the reply, and a reply that never closes the tag is requested again, up to twice ([#133](https://github.com/sandtable-ai/sandtable/issues/133)).
- `examples/freight`: offering `max_rate` as a logged counter-offer is no longer graded as disclosing it. The policy says so, and `never-disclose-ceiling` exempts `log_offer.counter_offer`; the README's design note explains why. Saying the ceiling any other way still fails ([#118](https://github.com/sandtable-ai/sandtable/issues/118)).
- `sandtable lint` ends with how many tasks a do-nothing agent passes, for example `a do-nothing agent passes 9 of 25` on the clinic example. It used to say the noop baseline passes every task that expects no write, which is false when a refusal must also look something up ([#100](https://github.com/sandtable-ai/sandtable/issues/100)).
- **Error messages** for the setup problems a new user hits first say what to do ([#96](https://github.com/sandtable-ai/sandtable/issues/96)):
  - a missing `ANTHROPIC_API_KEY` names the key, instead of the SDK's "Could not resolve authentication method"
  - an unreachable HTTP agent names its URL and the reason, instead of "fetch failed"
  - an unknown `--agent` lists the valid forms
  - a missing optional package says to install it next to `sandtable-ai`, or to name both packages with `npx -p`; a package installed on its own was invisible to `npx sandtable-ai`
  - `report` refuses a file that isn't a `results.json`
- **README**: every link and image is an absolute URL, so they work on the npmjs.com package page and in any viewer of the README shipped in the package, dark-mode screenshots included ([#103](https://github.com/sandtable-ai/sandtable/issues/103)).
- `init --openapi` refuses a Swagger 2.0 spec, a file without `openapi: 3.x` and a spec it can't draft a single tool from, and writes nothing. Before, it wrote a domain with 0 tools, which `validate` then rejected ([#98](https://github.com/sandtable-ai/sandtable/issues/98)).
- `validate` and `lint` reject a `never_disclose` invariant on a field that holds booleans, or only strings shorter than 3 characters, in the seed rows. Such an invariant could never fire, so a reviewer could believe the value was protected. `init --sop` drops such a draft with a warning when the domain has seed rows ([#116](https://github.com/sandtable-ai/sandtable/issues/116)).
- `sandtable --version` reports the installed version; 0.1.0-alpha.1 printed `0.1.0-alpha.0` ([#88](https://github.com/sandtable-ai/sandtable/issues/88)).
- `examples/freight` and `examples/clinic` work under `npx sandtable-ai` from any directory. When the folder isn't there, `validate`, `lint`, `review`, `run` and `leaderboard` use the copy bundled with the package and print its path; a folder of that name in the current directory still wins. The commands in the docs, the example READMEs and the plugin skills run as written. The `--prices` help and the leaderboard docs no longer point npm users at files that exist only in a clone ([#99](https://github.com/sandtable-ai/sandtable/issues/99)).
- `leaderboard` reruns a model when its agent spec changed under the same label (for example a newer model ID under "Claude Sonnet") or when what the agent or the caller is given changed, and says why, for example `stored results not reused: they are for agent scripted:careful, not scripted:naive`. Before, it reused the old results and ranked them under the new spec ([#127](https://github.com/sandtable-ai/sandtable/issues/127)).
- `leaderboard` grades a model's stored conversations again under the domain's current rules when it resumes, instead of reusing the verdicts they were stored with, so every row is graded by the same grader. No model is called: a fixed or added invariant or expectation updates the stored `results.json` and `report.html`, and the output says how many verdicts changed. A model reruns when the agent or the caller would be given something else (the policy, a tool, a seed record or a task's caller instructions), as `sandtable regrade` checks; an edit to grading alone no longer reruns it ([#140](https://github.com/sandtable-ai/sandtable/issues/140)).
- First-run polish ([#129](https://github.com/sandtable-ai/sandtable/issues/129)):
  - the next steps after `demo` and `init` are `npx sandtable-ai …` commands, which run as written however you installed sandtable, and the live demo suggests the cheaper `--user-model claude-haiku-5-5`. Before, they began with `sandtable`, which isn't on the PATH of `npx` and `uvx` users
  - an HTTP agent is named by its URL in summaries, reports and `results.json`, instead of `http:http://…`
  - `run --help` lists the `scripted:*` demo agents under `--agent`
- `run` and `demo --live` exit 1 and print the error when every trial ended in one, for example without `ANTHROPIC_API_KEY`, without an optional Bedrock package or with the agent's server down. Before, they printed a 0% score and exited 0 ([#95](https://github.com/sandtable-ai/sandtable/issues/95)).
- `npx sandtable-ai` on Node.js 20 prints no `EBADENGINE` warning, and installs with `engine-strict=true`: the CLI uses commander 14, which supports Node 20, instead of commander 15, which requires Node 22.12 ([#101](https://github.com/sandtable-ai/sandtable/issues/101)).
- **Python launcher**: the `sandtable` command becomes the `npx` process instead of waiting on it, so stopping it with SIGTERM (a process manager, a CI cancel) also stops the CLI. Without network it starts from npm's cache in about 4 seconds instead of 70. It tells you to install npm when Node.js is there but `npx` isn't, and the wheel ships the MIT license ([#104](https://github.com/sandtable-ai/sandtable/issues/104)).
- `sandtable.yaml`: a `policy`, `world` or `tasks` path to a missing file fails validation and names the file. Before, a misspelled `policy: ./polcy.md` passed `validate`, and every run gave the agent the text `./polcy.md` as its policy. YAML syntax errors now name the file they are in ([#97](https://github.com/sandtable-ai/sandtable/issues/97)).
