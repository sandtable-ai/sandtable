# Changelog

All notable changes to sandtable are documented in this file: the `sandtable-ai` CLI and library on npm, its Python launcher on PyPI, and the Claude Code plugin in this repository, which share one version number.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0, a minor release may change the domain spec, the CLI or the library API; every such change is marked **Breaking:** and says what to do.

## [Unreleased]

### Added

- **Library**: `parseDomain(value)` checks a domain built in code as `loadDomain` checks a file, the schema and then the cross-references, and throws a `DomainError`. A new page, [sandtable.dev/reference/library](https://sandtable.dev/reference/library), documents every export of the package ([#370](https://github.com/sandtable-ai/sandtable/issues/370)).
- `results.json` records the sandtable-ai that wrote it, as `sandtable: { version }`, and `sandtable regrade` adds `regradedWith`. When `regrade` refuses a run because what the agent or the caller is given changed, and the run came from another version, it says the version that ran it and the command that regrades it with that version, such as `npx sandtable-ai@0.2.1 regrade runs/results.json -d ./sandtable`. A leaderboard's resumed results stay as stored unless a verdict changes ([#372](https://github.com/sandtable-ai/sandtable/issues/372)).
- `sandtable run --fail-on-regression`, with `--baseline`: the run exits 1 when a task that passed every graded trial in the baseline fails one now, and names each such task with its passes before and after, so a pull request that breaks a task fails CI even when pass^k stays above `--fail-under`. Tasks that got worse without ever passing every trial, tasks whose test changed since the baseline, and new failing tasks are still listed but don't gate. Without `--baseline` it is a usage error (exit 2), before any trial runs ([#281](https://github.com/sandtable-ai/sandtable/issues/281)).
- `sandtable compare <baseline.json> <results.json>`: shows what changed between two runs of one domain that already exist, with the same block `run --baseline` prints (broken, worse, fixed, better and changed tasks, added and removed ones, pass^1 and pass^k before and after), without calling a model. Use it for a pull request's run and the base branch's made in separate CI jobs, or for runs made without `--baseline`. `--fail-on-regression` exits 1 when a task broke, and `-o <dir>` writes the newer run's `results.json` and `report.html` with the baseline attached. Runs of two domains exit 2 ([#285](https://github.com/sandtable-ai/sandtable/issues/285)).
- `sandtable run --floor <tag>=<pct>`, repeatable, gates one tag's pass^k as `--fail-under` gates the whole suite's, so a strong happy path can't carry weak refusals over the gate: `--floor refusal=100 --floor negotiation=70` exits 1 and names each tag below its floor, with or without `--fail-under`. A tag that no task in the run carries, a value that isn't `<tag>=<pct>`, a percentage outside 0 to 100 or a tag given twice stops the run before any trial with exit 2, so a typo can't make the gate pass. The **By tag** table in the terminal and in `report.html` shows each floor and marks a tag below it, and `results.json` records the floors as `floors` ([#283](https://github.com/sandtable-ai/sandtable/issues/283)).
- `sandtable leaderboard`: when the board runs critical tasks, a **Critical** column in the terminal table, `LEADERBOARD.md` and `leaderboard.html` shows how many each model passed in every trial, `3/3`, or `✗ 2/3: expired-insurance` with the ones it failed. Each row of `leaderboard.json` has them as `critical: { tasks, failed }`, and an error row from skipped trials has `skipped`, how many there were ([#284](https://github.com/sandtable-ai/sandtable/issues/284)).

### Changed

- **results.json**: `report`, `regrade`, `run --baseline` and `leaderboard` refuse a `results.json` whose format `version` is newer than the one they read, with exit 2 and a message saying to use a newer sandtable-ai, instead of reading fields that may have changed meaning. The version moves only when a field is removed or changes meaning, never for an added field, as `docs/reference/results-schema.mdx` now states. Every `results.json` sandtable has written is version 1, and a hand-made one without `version` is read as version 1, so none that loaded before is refused ([#349](https://github.com/sandtable-ai/sandtable/issues/349)).
- **Breaking:** **Library**: the package exports only its documented API, which 1.0 will keep stable. Removed:
  - the zod schemas (`DomainSpec`, `TaskSpec`, `ToolSpec`, `ParamSpec`, `TableSpec`, `OpSpec`, `CheckSpec`, `FieldRef`, `InvariantSpec`, `StateAssertSpec`, `CallExpectSpec`, `ExpectSpec`, `ReferenceCallSpec`, `PersonaSpec`, `GivenSpec`): use `parseDomain(value)` instead of `DomainSpec.parse(value)`. The TypeScript types (`Domain`, `Task`, `CallExpect`, …) are still exported, so zod's version is no longer part of sandtable's API.
  - `runEpisode`, `gradeTrial`, `regradeTrial`, `checkCall`, `invariantTool`: use `runSuite` with `taskIds` and `k: 1`, or `regradeSuite`.
  - `worldFor`, `seedFor`, `diffSnapshots`: use `new World(domain.world)` and its `snapshot()`.
  - `agentSystemPrompt`: an agent receives the same prompt as `AgentContext.system`.
  - `userSystemPrompt`, `STOP_TOKEN`, `callerNotes`, `binom`, `DEFAULT_MODEL`, `DEFAULT_OPENAI_BASE_URL`: internals with no replacement; a run's `results.json` still carries each trial's `callerNotes`.

  Code that imports only the documented exports is unaffected ([#370](https://github.com/sandtable-ai/sandtable/issues/370)).
- **Breaking:** **Node.js and Python**: sandtable-ai needs Node.js 22 or later (`engines.node` is `>=22`), and the PyPI launcher needs Python 3.10 or later. Node.js 20 reached end of life on 2026-04-30 and Python 3.9 in October 2025, and 1.0 shouldn't promise to keep supporting them. On Node 20, `npm install` and `npx sandtable-ai` warn about the engine, and an install with `engine-strict` fails; `pip install sandtable-ai` on Python 3.9 keeps installing 0.2.1, the last launcher that supports it, which runs `npx sandtable-ai@0.2.1`. Upgrade Node.js to 22 or later (a CI job's `node-version: 22`), and Python to 3.10 or later for the launcher. CI now tests Node 22, 24 and 26 ([#350](https://github.com/sandtable-ai/sandtable/issues/350)).
- **Breaking:** `sandtable leaderboard`: a model that failed any trial of a critical task now ranks below every model that failed none, whatever its pass^k, since `run` would block its release; within each group, models rank by pass^k as before. A board with critical tasks can therefore order its rows differently from 0.2: a script that reads the top row of `leaderboard.json` as the best model should check its `critical.failed` too ([#284](https://github.com/sandtable-ai/sandtable/issues/284)).
- **Breaking:** `sandtable leaderboard`: a trial that ended in an error now counts as `run` counts it. One that ended in an error after the agent broke a hard rule or called a forbidden tool counts as failed, so the model is ranked with it instead of shown as an error row, and its results are stored and reused like any complete run. Only a skipped trial, one that ended in an error before the agent broke anything, still makes the model an error row, whose message now reads `N of M trial(s) skipped after an error: <the first error>` instead of `N of M trial(s) crashed: …` ([#284](https://github.com/sandtable-ai/sandtable/issues/284)).
- **Breaking:** `sandtable demo --live` now applies `run`'s gates: it exits 1 when any trial of one of the freight example's critical tasks failed, and 2 when a trial was skipped after an error. Before, it exited 0 whatever the agent did, unless every trial ended in an error. A script that runs `demo --live` and expects 0 should accept 1, as with `run`: `npx sandtable-ai demo --live || [ $? -eq 1 ]` ([#284](https://github.com/sandtable-ai/sandtable/issues/284)).

### Fixed

- **Docs**: the CLI reference lists `NO_COLOR`, and the spec reference describes `source: { file, quote }` on invariants and tasks. Tests now fail when a reference page misses a command's option, an environment variable, a spec key or a `results.json` field, so the pages stay complete ([#371](https://github.com/sandtable-ai/sandtable/issues/371)).

## [0.2.1] - 2026-10-22

A patch release with no breaking changes: `validate` names the installed version and a command to check a newer one when a key is unknown, a model whose reply is only reasoning is asked again instead of leaving the caller in silence, a module agent's load error reads as two sentences, and the plugin checks a failed rule against its SOP quote before blaming the agent.

### Added

- `sandtable validate`, and every command that loads a domain: an unrecognized key is followed by a line naming the installed version, such as `sandtable-ai 0.2.1 doesn't know this key: check its spelling, or whether a later release added it`, so a key from a newer release than the one installed is easy to tell from a typo ([#341](https://github.com/sandtable-ai/sandtable/issues/341)).

### Changed

- **Claude Code plugin**: before blaming the agent for a failed invariant, `running-and-reading-results` and the `failure-triager` subagent read the rule's `source.quote` and check that the SOP requires what the rule checks: the same order of calls, bound and condition. A rule stricter than the SOP is attributed to the task spec, with the fix to relax it or make it `soft: true` and confirm with `regrade`, instead of the agent being blamed for following the SOP ([#343](https://github.com/sandtable-ai/sandtable/issues/343)).
- **Roadmap**: `ROADMAP.md` and sandtable.dev/roadmap list what 0.2.0 shipped, instead of calling it unreleased, and show the path to 1.0: 0.3.0 as the last release that may change the contracts, what 1.0 promises to keep stable, and what comes after it ([#347](https://github.com/sandtable-ai/sandtable/issues/347)).

### Fixed

- `run --agent <module>`: when a JS or TS agent fails to load, sandtable's advice now starts a new sentence after Node's error, as in `Unexpected token 'export'. Node read it as CommonJS, …`, instead of running on from it ([#345](https://github.com/sandtable-ai/sandtable/issues/345)).
- **Agents and callers on other models**: a reply that is nothing but reasoning, with no tool call, no longer reaches the other side as silence. The `openai:` adapter (agent and caller) and the Bedrock Converse agent (`bedrock:<model-id>`) removed the reasoning and sent an empty message, so the caller heard nothing, asked "Hello?" and the turn counted against `max_turns`; gpt-oss-120b through Bedrock's OpenAI-compatible endpoint did this in 4 of 56 agent turns. Both now ask for such a reply again, up to twice, as Converse already did for reasoning that never closes, and the discarded replies never enter the conversation. If the third reply is still empty, it is sent as before and counted in `results.json`'s `usage` as `emptyAfterStrip`, next to `reasoningStripped`, so a run shows how often the other side heard silence; the terminal summary and the HTML report show the count when it isn't zero ([#332](https://github.com/sandtable-ai/sandtable/issues/332)).

## [0.2.0] - 2026-10-22

A release with breaking changes that closes the loop in CI: `critical: true` tasks, argument matchers and per-task `given`, `run --baseline` with what changed per task, passed, failed, flaky and skipped verdicts with errored trials skipped, exit 1 for a failed gate and 2 for an error, `init` drafts that keep their sources' facts, show their plan and cost with `--dry-run` and print what they cost, a simulated caller that says it doesn't know instead of guessing, and a Claude Code plugin installed from the release; read the seven **Breaking:** entries under Changed before upgrading.

### Added

- **Domain spec**: a task's `called` and `not_called` entries can say which call, as `{ tool, args }` with a where clause on the call's arguments, such as `called: [{ tool: transfer_to_human, args: { mc_number: "100101" } }]` or `not_called: [{ tool: book_load, args: { load_id: L-1004 } }]`. A failed check says how the closest call differed, and `validate` rejects an argument the tool doesn't have or an unknown operator. Plain tool names work as before, and the library exports the entry's schema as `CallExpectSpec` ([#25](https://github.com/sandtable-ai/sandtable/issues/25)).
- **Critical tasks**: `critical: true` on a task marks a release blocker. `sandtable run` exits 1 when any trial of a critical task fails, with or without `--fail-under`, and names those tasks. The terminal summary and the HTML report list critical tasks first and mark them, `results.json` carries `"critical": true` on them, and the library exports `criticalFailures`. The bundled freight and clinic examples mark three refusals each as critical, so their naive agents' runs now exit 1 ([#28](https://github.com/sandtable-ai/sandtable/issues/28)).
- **Domain spec**: a task can change the world it starts in with `given`, instead of a seed row only it uses or a copy of the domain. `given.rows` merges rows into the seed by each table's key for that task only: a seeded key patches the fields listed (the same carrier with `insurance_status: expired`), a new key adds a row. `given.context`, such as a caller ID or a trigger payload, is given to the agent and not to the simulated user: it follows the policy in the default system prompt, and an agent over HTTP or a JS/TS module agent receives it as `context`. `lint` and `regrade` use the patched world, and a value in the context counts as shown for `never_disclose` ([#37](https://github.com/sandtable-ai/sandtable/issues/37)).
- `sandtable run --baseline <results.json>` compares the run with an earlier run of the same domain, such as the last run on `main`. The summary lists each task that broke, got worse, got fixed or got better, new failures first, counts added, removed and unchanged tasks, and shows pass^1 and pass^k before and after over the tasks both runs ran. A task whose test changed since the baseline is listed as `changed` instead of fixed or broken, and left out of the scores: each task in `results.json` carries two short hashes, `inputs` (what the agent and caller are given and the world they act in) and `grading` (its expectations and the invariants), and a task whose hash differs from the baseline's changed. The summary also names what else differs: the agent, the simulated user, k, and how many tasks' tests changed; a baseline written by 0.1.x has no such hashes, and the summary says it can't tell. The baseline is read before any trial runs, so a wrong file or another domain's run costs no model calls, and the exit code is unchanged. `results.json` keeps the baseline's per-task results as `baseline`, the HTML report opens with the changes and marks regressed tasks, and `report` and `regrade` show them again without the baseline's file. The library exports `compareRuns` and `baselineSnapshot` ([#12](https://github.com/sandtable-ai/sandtable/issues/12), [#309](https://github.com/sandtable-ai/sandtable/issues/309)).
- `sandtable run`: each task gets a verdict over its graded trials, `passed`, `failed`, `flaky` or `skipped`, and a 95% Wilson interval for its pass rate, and runs report pass@k next to pass^k, the flip rate (the share of tasks that are flaky) and the flaky tasks. The terminal summary and the HTML report show them, and `results.json` adds `passAt`, `flipRate`, `flaky` and `skipped`, and per task `graded`, `skipped`, `verdict` and `interval`. The library exports `passAtK`, `wilsonInterval`, `trialStatus` and the `Verdict` type ([#27](https://github.com/sandtable-ai/sandtable/issues/27)).
- **Domain spec**: a `reference` call can be one the API rejects, marked `expect_error: true` or with text its error contains, such as `expect_error: not found`. `lint` then requires that call to fail, so a refusal task whose correct agent looks up an unknown ID is proven `solvable` instead of `solvable ?`, and a domain edit that drops the rejection is caught. A call with arguments the tool rejects is still a `lint` error. The freight example's `unknown-mc-number` uses it, and the library exports `ReferenceCallSpec` ([#274](https://github.com/sandtable-ai/sandtable/issues/274)).
- `sandtable init`: after `--sop` and after `--transcripts`, it prints the step's token usage per model and an estimated cost at list prices, as `run` does: one Claude call for the SOP and one per transcript, so an engineer can see what a draft cost before drafting from many more transcripts ([#297](https://github.com/sandtable-ai/sandtable/issues/297)).
- `sandtable init --dry-run`: with `--sop` or `--transcripts`, prints a plan line (the model calls, 1 for the SOP and 1 per transcript, the model, the provider and region, and a cost bound at list prices) and stops: no model call, nothing written, and no API key, AWS credentials or Bedrock package needed. With `--openapi`, it lists the files it would write. A real run prints the same plan line before its first model call ([#296](https://github.com/sandtable-ai/sandtable/issues/296)).
- `init --transcripts`: each drafted task gets `reference` calls, the tool calls a correct agent makes in order, so `lint` can prove it solvable instead of reporting `solvable ?`. `init` lints each drafted task, replaying its reference, and keeps one that fails for review, with a warning and a `# TODO(review): lint: ...` comment above it. References list only calls that succeed, so a refusal whose correct path includes a call the API rejects may have lookups only. A drafted range, such as a negotiated rate between two bounds, now keeps both bounds; before, only the last condition on a field was kept ([#278](https://github.com/sandtable-ai/sandtable/issues/278)).

### Changed

- **Breaking:** `sandtable run`: a trial that ends in an error, such as a rate limit or timeout that outlasted the retries or an agent endpoint that went down, is now skipped instead of failed, unless the agent had already broken a hard invariant or called a `not_called` tool. A skipped trial is left out of pass^k, pass@k and the per-tag scores, carries `skipped: true` in `results.json` and is listed under **Skipped trials**, and `run` exits 2 when any trial was skipped, even without `--fail-under`, because the run is incomplete. A CI job that passed with a few errored trials now fails: fix the cause, such as credentials or a lower `--concurrency`, and rerun ([#27](https://github.com/sandtable-ai/sandtable/issues/27)).
- **Breaking:** library: in the exported `Task` type, `expect.called` and `expect.not_called` entries are `string | { tool, args }` (the new `CallExpect`) instead of `string`, since a task can match a call's arguments. TypeScript code that reads them as tool names must handle the object form, e.g. `typeof e === "string" ? e : e.tool`. Domains that list tool names are unchanged ([#25](https://github.com/sandtable-ai/sandtable/issues/25)).
- **Breaking:** `examples/freight` and `examples/clinic`: three refusal tasks in each are now `critical: true`, so a run of their naive scripted agents (`--agent scripted:naive` or `scripted:clinic-naive`) exits 1 instead of 0. A script that renders their reports should accept a failed gate; `demo` and the careful agents are unaffected ([#28](https://github.com/sandtable-ai/sandtable/issues/28)).
- **Breaking:** `sandtable validate`: a domain with an unknown operator, `$in` or `$nin` without a list, or a top-level `$` key in any where clause now fails validation, so no command loads it. On 0.1.x it loaded, then crashed mid-run or silently matched nothing. Fix the clause at the path `validate` names ([#279](https://github.com/sandtable-ai/sandtable/issues/279)).
- **Breaking:** **Simulated caller**: its prompt changed, and the prompt is part of a run's `inputs` hash. So `sandtable regrade` refuses a run stored by 0.1.x, and `sandtable leaderboard` stops without running anything when a model's stored results come from 0.1.x. Regrade such a run with the version that made it (`npx sandtable-ai@0.1.2 regrade …`), and for a board, move those models' folders away or pass `--no-resume`, which reruns every model and costs model calls. Scores of new runs can differ from 0.1.x runs of the same agent, since the caller now says it doesn't know a fact its instructions leave out; `run --baseline` against a 0.1.x run says the prompts changed. Review tasks whose caller instructions leave out a fact the agent will ask about, such as an item's condition, a receipt or a date, and add it to `user.instructions` ([#287](https://github.com/sandtable-ai/sandtable/issues/287)).
- **Breaking:** **CLI exit codes**: a failed gate exits 1 and an error exits 2, as `grep` and `diff` do. 1 means a gate failed on a complete result: `run` below `--fail-under` or with a failed critical task, `lint` errors, `validate --strict` with pending items, and `validate` or `lint` on a domain that exists but is invalid. 2 means the command couldn't do its job: a usage error (an unknown command or option, a missing argument, an invalid value, or no command at all), a missing or unreadable file, no domain at the path, an invalid domain for any other command, an adapter that can't be built, a `run` or `demo --live` in which every trial ended in an error, a `run` with skipped trials (even when a gate failed too), and a `leaderboard` on which every model failed. Before, all of these exited 1. Help, `--version` and 141 for a closed pipe are unchanged. A CI step that treats any non-zero status as a failure needs no change; one that checks for 1 to mean an error must accept 2, and one that lets a failing agent through, to render its report, can accept only 1 with `|| [ $? -eq 1 ]` ([#282](https://github.com/sandtable-ai/sandtable/issues/282)).
- **Status**: the README, the docs and the PyPI classifier describe sandtable as beta instead of early alpha. It works and is tested, and the spec and outputs may still change before 1.0 ([#267](https://github.com/sandtable-ai/sandtable/issues/267)).
- **Leaderboard docs**: the freight board's history includes its re-render at v0.1.2, which ran no model and changed no verdict, and `leaderboard.json` is described as recording 0.1.2 at `eb4cfd2` ([#260](https://github.com/sandtable-ai/sandtable/issues/260)).
- **Roadmap**: the v0.3 section of `ROADMAP.md` and sandtable.dev/roadmap separates what is done on `main` and not yet released (`run --baseline`, reliability verdicts, critical tasks, argument matchers and `given`) from what is left, including the follow-ups filed since: a regression gate, exit codes, per-tag floors, the leaderboard and `demo --live`, and `sandtable compare` ([#288](https://github.com/sandtable-ai/sandtable/issues/288)).
- **Claude Code plugin**: after a fix, `running-and-reading-results` and the `failure-triager` subagent confirm a change to grading only (an invariant, an expectation, a `never_disclose` rule) with `sandtable regrade`, which calls no model, and rerun with `--tasks` only the tasks whose caller instructions, tools, policy or agent changed. They fix grading and regrade before changing a caller's instructions, since `regrade` refuses a run once any caller prompt changed ([#300](https://github.com/sandtable-ai/sandtable/issues/300)).
- **Claude Code plugin**: attribution no longer blames an agent that stops because the records contradict the request: `running-and-reading-results` checks the seed rows and `given.rows` against the caller's instructions, and a disagreement is the task's fault. A fact the caller states that its instructions lack is fixed in the task's instructions. Before recommending a model from a leaderboard, the skill has `failure-triager` attribute every failure of the top candidates, since a cheaper model's only failure may be the task's ([#299](https://github.com/sandtable-ai/sandtable/issues/299)).
- **Breaking:** `sandtable report -o`: a path that doesn't end in `.html` is now a folder, and the report goes in it as `report.html`, as `run -o` and `regrade -o` take a folder. Before, `report results.json -o runs/rerender` wrote an HTML file named `rerender` with no extension. A path ending in `.html` still names the file itself, so a script that passes a file name without `.html` should add it ([#317](https://github.com/sandtable-ai/sandtable/issues/317)).
- `sandtable demo --live`: the simulated caller now defaults to Claude Haiku 5.5 instead of the agent's Claude Opus 5.5, about half the cost of a first live run, as the docs already recommended with `--user-model claude-haiku-5-5`. `--user-model` still picks another caller, the agent keeps its default, and `run --user claude` is unchanged ([#329](https://github.com/sandtable-ai/sandtable/issues/329)).
- **Claude Code plugin**: the `drafting-a-domain` skill says how to install the CLI with its optional packages. Prefer a project install (`npm install --save-dev sandtable-ai @anthropic-ai/bedrock-sdk`, then `npx sandtable-ai <command>`). It lists which package each path needs: `@anthropic-ai/bedrock-sdk` for `--provider bedrock`, `@aws-sdk/client-bedrock-runtime` for a `bedrock:` agent and `@aws-sdk/credential-providers` for `--aws-profile`. Without an install, the form is `npx -p sandtable-ai -p <package> sandtable <command>`, where the command is the bin, `sandtable`. It also says to keep runs inside the project. An agent no longer has to read sandtable's compiled code to run `init` on Bedrock ([#295](https://github.com/sandtable-ai/sandtable/issues/295)).
- **Claude Code plugin**: before `init --sop` or `init --transcripts`, the `drafting-a-domain` skill has the agent run the same command with `--dry-run` and show the engineer its plan line (model calls, model, provider and a cost bound), even when model steps are already authorized. When they are, it goes on to the paid run after the plan, instead of reporting the cost afterwards; otherwise it asks. It suggests `-m claude-sonnet-5-5` for a first draft of many transcripts. `init` then prints what the step actually cost ([#296](https://github.com/sandtable-ai/sandtable/issues/296)).
- **Claude Code plugin**: the review checklists of the `drafting-a-domain` skill, and the review workflow docs, gain the checks a run on real support chats needed. A drafted task keeps its transcript's facts and outcome, every row it touches agrees with the transcript, and its caller's instructions state every fact the agent will ask about. An ambiguous case in the SOP goes to the customer, and until then the task grades only what every reading agrees on. A drafted invariant that requires a step the agent can skip while still deciding correctly becomes `soft: true`, or checks the decision itself ([#298](https://github.com/sandtable-ai/sandtable/issues/298)).

### Fixed

- **Docs**: sandtable.dev documents the latest release instead of `main`, so a user of the published CLI no longer finds flags and spec keys it doesn't have yet, such as `--baseline` or `critical: true` while npm served 0.1.2. The site deploys from a `docs-live` branch that each stable release moves to its tag ([#313](https://github.com/sandtable-ai/sandtable/issues/313)).
- `sandtable validate`: an unknown operator such as `$like`, `$in` or `$nin` without a list, or a top-level key such as `$or`, now fails validation in every where clause, with the clause's path: a tool's `list` op and `checks`, invariant `require.where` and `never.when`, and a task's `expect.state` `where` and `fields`. Before, only a `called`/`not_called` entry's `args` were checked: elsewhere, `lint` and `run` stopped on a bare "Unknown operator" without writing results, or a clause matched nothing and a valid call was rejected ([#279](https://github.com/sandtable-ai/sandtable/issues/279)).
- **CLI**: a path that names nothing now says which argument or option it came from, instead of Node's `ENOENT: no such file or directory, open '…'`: `report`, `regrade`, `run --prices` and `--baseline`, `leaderboard -m` and `--prices`, and `init --openapi`, `--sop` and `--transcripts`, e.g. `--prices: no file at prices.json`. A directory given where a file is expected says so, and points at the `results.json` inside it when there is one. `init` reads every input before drafting, so a wrong `--transcripts` path no longer fails after `--sop` has called a model, and a `--transcripts` directory with no `.txt` or `.md` file is named. `report -o` creates the directory it writes into, as `run -o` does ([#280](https://github.com/sandtable-ai/sandtable/issues/280)).
- `init --transcripts`: a drafted task keeps the facts its transcript states. An existing row is reused only when every fact the transcript states about it matches, so a second caller with the same name but another membership level or order gets a new row instead of a task rewritten to fit the first one. When a draft still reuses a row that contradicts its transcript, `init` keeps the task for review, prints a warning naming the row and each differing field, and writes it as a `# TODO(review):` comment above the task ([#276](https://github.com/sandtable-ai/sandtable/issues/276)).
- `init --sop`: every rule the SOP states now ends up as an invariant or a `Soft rule` comment. Before, a rule it couldn't express, such as a cancellation window with an exception, was in neither list. Claude lists the SOP's rules first and maps each one. Each soft rule comment says why no invariant checks it, such as `needs today's date`, `depends on a fact no record holds` or `needs either of several tools first`. A rule whose drafted invariant was dropped, or that the draft mapped nowhere, is listed too, with a warning ([#277](https://github.com/sandtable-ai/sandtable/issues/277)).
- **Simulated caller**: a fact its instructions don't state about the caller, its account or what it is calling about is now unknown to it, so it answers "I'm not sure" instead of guessing, also to yes-or-no questions such as an item's packaging or a receipt. It also no longer describes the agent or explains how it is answering. Reports flag the turns where it still steps out of its role, talking about its instructions, saying its goal is met or talking about the agent in the third person: the terminal summary and the HTML report list them as **Caller notes** and mark them in the transcript, and `results.json` has `callerNotes` per trial and a count per run. They never change a verdict. The library exports `callerNotes`. Runs stored by 0.1.x can't be regraded or resumed by this version: see the **Breaking:** entry under Changed ([#287](https://github.com/sandtable-ai/sandtable/issues/287)).
- **Claude Code plugin**: the marketplace installs the plugin from `plugin/` at the latest release's tag instead of from `main`, so its skills describe the CLI that `npx sandtable-ai` runs and its version is that release's. Before, they could document features only `main` had, such as `given` and `critical: true` under 0.1.2, and an agent that found them missing guessed which features existed. Existing installs get the pinned plugin with `/plugin marketplace update sandtable`. The skills now say to learn what the installed CLI supports from `npx sandtable-ai --version`, `--help` and `validate`, never from sandtable's own code, in npx's cache or in the project's `node_modules/sandtable-ai`, and that a Claude model on Bedrock takes its plain name (`-m claude-sonnet-5-5`), which sandtable maps to the region's inference profile. The `writing-good-tasks` and `running-and-reading-results` skills also load for requests about release-blocker (critical) tasks and CI gates, so their guidance reaches the agent when it's asked to make a task a release blocker. To try the skills from a clone, start Claude Code with `claude --plugin-dir ./plugin` ([#301](https://github.com/sandtable-ai/sandtable/issues/301)).
- `sandtable run --agent <module>`: a `.ts` or `.js` agent that Node loads as CommonJS, as in a project made with `npm init` (`"type": "commonjs"`), now fails with what to do: rename it to `.mts` or `.mjs`, or set `"type": "module"` in the nearest package.json. Before, it showed only Node's `Unexpected token 'export'`. On a Node too old to load TypeScript, the error says it needs Node 22.18 or later. The bring-your-agent guide and the README say a module agent must be an ES module ([#305](https://github.com/sandtable-ai/sandtable/issues/305)).
- `sandtable run` and `demo --live`: before the first trial, they check that the agent and the simulated user can start, and when one can't, they name it and the problem, run nothing, write nothing and exit 2. Before, a missing `ANTHROPIC_API_KEY` made every trial fail one by one (`demo --live` skipped all 50 before saying why), and when only one side lacked credentials, the other side's calls were made and billed in every trial. The checks cost nothing: Claude on the Anthropic API lists one model, Claude on Bedrock and `bedrock:` agents resolve their AWS credentials, region and optional package locally, and an HTTP agent must accept a connection, with no request sent ([#316](https://github.com/sandtable-ai/sandtable/issues/316)).
- **Domain errors**: a schema or cross-reference error in an included file, such as a task in `tasks.yaml` with an unknown key or an argument its tool doesn't have, now names that file instead of `sandtable.yaml`, as YAML syntax errors already did. Problems in several files are listed under each one. `lint` says "needs a row in `orders`" instead of "needs a orders row" ([#317](https://github.com/sandtable-ai/sandtable/issues/317)).
- **Agents and callers on other models**: reasoning a model writes into its reply text no longer reaches the other side of the conversation or the graders. The `openai:` adapter removed only `<think>` blocks, so gpt-oss through Bedrock's OpenAI-compatible endpoint, which writes `<reasoning>`, leaked its reasoning: as the agent it was scored as speech (`never_disclose` included), and as the simulated caller it quoted its hidden instructions to the agent. The Bedrock Converse agent (`bedrock:<model-id>`) removed only `<reasoning>`, and missed gpt-oss's occasional `<analysis>`. Both adapters, for the agent and for the `openai:` caller, now remove `<think>`, `<thinking>`, `<reasoning>` and `<analysis>` blocks, a closing tag whose block opened before the reply, and an opening tag that never closes with everything after it. `usage` counts the replies that had reasoning removed as `reasoningStripped`, shown in the terminal summary and the HTML report. Runs of such models through these adapters scored leaked reasoning as speech before; `regrade` can't change that, since the stored transcript holds the leaked text and the conversation would have gone otherwise, so rerun them. On the published freight leaderboard, one of gpt-oss-120b's `never-disclose-ceiling` failures came from an `<analysis>` block ([#308](https://github.com/sandtable-ai/sandtable/issues/308)).
- `init --sop`: a drafted invariant's conditions can use `$in`, `$nin` and `$exists`, so a rule that a call must include an argument in some cases, such as a refund by check needing the mailing address, drafts as a `never` with `when: { method: { $in: [...] }, mailing_address: { $exists: false } }` instead of a soft rule that says it can't be expressed. Two conditions on the same field, such as a lower and an upper bound, are both kept; before, the second replaced the first ([#314](https://github.com/sandtable-ai/sandtable/issues/314)).
- `docs/quickstart`: the toy HTTP agent, in Node and in Python, remembers the carrier it verified under the `session_id` sandtable sends with every step, so after a verified MC number it says a rep will finish the booking instead of asking for the MC number again on every turn. It still scores pass^1 36.0% on the freight example ([#270](https://github.com/sandtable-ai/sandtable/issues/270)).
- `init --transcripts`: the drafting prompt now shows each tool param's allowed values, whether it's optional and its description, as `init --sop`'s does, so drafted references use the API's values (`by_mail`) instead of the transcript's wording ("By Mail"), which failed the draft-time lint. A drafted value that differs from exactly one allowed value only in case, spaces or dashes is replaced by it, with a warning, and drafted end-state conditions can use `in`, `nin` and `exists` like `init --sop`'s ([#336](https://github.com/sandtable-ai/sandtable/issues/336)).
- **Claude Code plugin**: the drafting and results skills say what to do when a command fails with `OpenSSL configuration error … openssl.cnf … Operation not permitted`: Claude Code's sandbox blocked Node from reading Homebrew OpenSSL's config, so rerun it with `OPENSSL_CONF=/dev/null` in front ([#334](https://github.com/sandtable-ai/sandtable/issues/334)).

## [0.1.1] - 2026-10-21

A bug-fix release with no breaking changes: names like `toString` are checked like any other in tool arguments and invariants, `init --openapi` drafts OpenAPI 3.1 nullable fields, a closed pipe exits 141 instead of crashing, and `leaderboard` names unreadable stored files and keeps a full board's crashed run during a quick check.

### Fixed

- `world`: a tool argument named like a built-in JavaScript property, such as `toString` or `constructor`, is now rejected as an unknown argument like any other name the tool doesn't have, and a tool param with such a name that the agent omits counts as missing (its default applies) instead of failing with "must be a string" ([#233](https://github.com/sandtable-ai/sandtable/issues/233)).
- `init --openapi`: a body field, query or path param with an OpenAPI 3.1 nullable type such as `type: [string, "null"]` becomes a param of its other type, as a 3.0 `nullable: true` one does, instead of being skipped as not a scalar. `[object, "null"]` bodies and `[array, "null"]` responses are read too, and a nullable enum's `null` is left out of the param's `enum`, so the draft validates ([#232](https://github.com/sandtable-ai/sandtable/issues/232)).
- **CLI**: piping any command's output into a reader that stops early, such as `head` or a `less` quit before the end, now stops the command quietly with exit 141, as Unix tools such as `git` do (128 + `SIGPIPE`), instead of crashing with an `EPIPE` stack trace and exit 1 ([#214](https://github.com/sandtable-ai/sandtable/issues/214)).
- `sandtable leaderboard`: a model's stored `results.json` or `run.json` that isn't valid JSON, or isn't the file its name says, no longer stops the board with a bare parser error. The board still stops before anything runs, and now lists every such file with its model's label and says how to recover: fix the file, or move that model's folder away to rerun the model ([#209](https://github.com/sandtable-ai/sandtable/issues/209)).
- `sandtable leaderboard`: a quick check (`-t`, another `-k` or caller) on the same `-o` no longer deletes or overwrites the `crashed/` run of a full board, which can hold the only copy of partly paid conversations. A good run removes only a crashed run of the same tasks, k and caller, a crashing run of other tasks goes beside it in `crashed-2/`, and the output names every crashed run it kept ([#208](https://github.com/sandtable-ai/sandtable/issues/208)).
- **Domain spec**: an invariant that names a tool argument the tool doesn't have, such as `key_arg: toString` or `same: [constructor]`, now fails validation like any other unknown param. Before, a name inherited from JavaScript's `Object.prototype` passed `validate --strict`, and the invariant then failed the agent's trials at run time ([#245](https://github.com/sandtable-ai/sandtable/issues/245)).

## [0.1.0] - 2026-10-20

First public release. sandtable rehearses an AI agent on a simulated copy of one customer's world: a simulated caller with a hidden goal talks to the agent, the agent's tool calls run against stateful mocks of the customer's systems, and every trial is graded without a judge model into pass^k.

### Added

- **Domain spec** (`sandtable.yaml`): world tables with seed rows, tools as atomic ops with checks and defaults, policy invariants, caller personas, and tasks with a hidden goal and an expected end state. A `policy`, `world` or `tasks` path to a missing file fails validation and names the file, and a YAML syntax error names its file ([#97](https://github.com/sandtable-ai/sandtable/issues/97)).
- **Simulation**: every trial starts from a fresh copy of the world. The simulated caller follows its task's instructions over its persona, says only what a customer would say aloud, asks for nothing its goal doesn't mention, and hangs up once it is transferred ([#85](https://github.com/sandtable-ai/sandtable/issues/85)).
- **Grading**, deterministic:
  - the end state, required and forbidden tools, and invariants checked on every tool call: `before`, `require`, `limit` (with strict bounds `lt` and `gt`), `match` and `never`
  - `never_disclose` on the agent's messages. A value counts only once the agent has been shown it, in a tool result or its system prompt, and only in the order the conversation happened: a value the caller said first isn't a leak, and an `unless` exception (one, or a list) allows its value only from the agent turn it was made in. `never_with` lists words that make a shown value a leak wherever a sentence says both, so "$2,350 is our max" fails. Unicode hyphens read as `-` ([#86](https://github.com/sandtable-ai/sandtable/issues/86), [#132](https://github.com/sandtable-ai/sandtable/issues/132), [#136](https://github.com/sandtable-ai/sandtable/issues/136), [#166](https://github.com/sandtable-ai/sandtable/issues/166), [#180](https://github.com/sandtable-ai/sandtable/issues/180))
  - soft invariants: `soft: true` on any kind checks it as usual, but breaking it never fails a trial. Results, reports and the leaderboard show how often each was broken, out of the trials where it applied ([#120](https://github.com/sandtable-ai/sandtable/issues/120))
  - a YAML number matches a string with the same digits (`100101` and `"100101"`); zero-padded IDs such as `"007"` still differ from `7`
  - pass^k, failure-mode clustering and per-tag scores
- **`sandtable init`** drafts a domain from what a customer hands you: an OpenAPI 3.x spec (deterministic; a Swagger 2.0 file, or a spec it can't draft a single tool from, is refused and nothing is written), an SOP (invariants that quote their source) and call transcripts (tasks, personas and fictional seed rows, with PII scrubbed locally). From OpenAPI, it merges `allOf`-composed schemas, gives a field like `@type` or `pickup-window` a param named `at_type` or `pickup_window` that maps back to it, seeds rows from schema and media-type examples (keeping the fullest example per key, with a warning), and skips the webhook listener and subscription paths a client implements, OpenAPI 3.1 `webhooks` and `callbacks`, naming each one. Everything stays `review: pending` until accepted ([#98](https://github.com/sandtable-ai/sandtable/issues/98), [#219](https://github.com/sandtable-ai/sandtable/issues/219), [#220](https://github.com/sandtable-ai/sandtable/issues/220), [#221](https://github.com/sandtable-ai/sandtable/issues/221), [#223](https://github.com/sandtable-ai/sandtable/issues/223)).
- **`sandtable validate`** and **`sandtable lint`**. `lint` proves each task is ready, solvable (by reference replay), non-vacuous and graded, without model calls, and ends with how many tasks a do-nothing agent passes. Both reject a `never_disclose` invariant that could never fire (on booleans, or on strings shorter than 3 characters), which `init --sop` drops with a warning. `validate` fails when a tool's ops or checks refer to a param the tool doesn't have (`"$loadId"` where the param is `load_id`), reading references exactly as a run does, so a literal like `"$/hr"` or `"$5"` stays valid. It warns about a protected field the agent is never shown ([#100](https://github.com/sandtable-ai/sandtable/issues/100), [#116](https://github.com/sandtable-ai/sandtable/issues/116), [#174](https://github.com/sandtable-ai/sandtable/issues/174), [#223](https://github.com/sandtable-ai/sandtable/issues/223)).
- **`sandtable run`**:
  - prints a terminal summary whose failure modes fit an 80-column terminal
  - writes `results.json` with the run's `runId` and an `inputs` hash of what the agent and the caller were given
  - writes a self-contained HTML report with transcripts, tokens, estimated cost and turn latency, rule ids on the tool calls that broke them, and world changes shown as before → after
  - `--fail-under` gates CI, and `--open` opens the report
  - a run where every trial errored exits 1 and prints the error
  - `maxTokensStops` counts the replies that stopped at the output-token limit ([#70](https://github.com/sandtable-ai/sandtable/issues/70), [#79](https://github.com/sandtable-ai/sandtable/issues/79), [#80](https://github.com/sandtable-ai/sandtable/issues/80), [#95](https://github.com/sandtable-ai/sandtable/issues/95), [#173](https://github.com/sandtable-ai/sandtable/issues/173))
- **`sandtable regrade`** re-scores a past run's stored trials after you edit an invariant, an expectation or a `never_disclose` rule, without calling a model. It replays each trial's tool calls against a fresh world and grades the conversation as a live run would. It refuses when a replayed call returns something other than what the agent saw, or when the agent or the caller would be given something else now. `--domain` is required, since `results.json` records only the domain's name; a `--domain` of another domain says so, and which `name:` to look for. The library exports `regradeSuite`, `regradeTrial` and `RegradeError` ([#32](https://github.com/sandtable-ai/sandtable/issues/32), [#218](https://github.com/sandtable-ai/sandtable/issues/218)).
- **`sandtable leaderboard`** ranks several agents on one domain under the same simulated caller, next to a do-nothing baseline, by pass^k. Each row has pass^1, rule violations, the top failure, how often each soft rule was broken, cost per trial (the agent's model only) and p95 turn latency. It writes `leaderboard.json`, `LEADERBOARD.md`, `leaderboard.html`, and a folder per model with its `results.json`, `report.html` and `run.json` ([#93](https://github.com/sandtable-ai/sandtable/issues/93)):
  - **Resume.** A rerun reuses a model's stored conversations when the agent spec, effort, domain, k, caller, tasks, provider and region match, and the agent and the caller would be given the same inputs. They are graded again under the domain's current rules, so a fixed invariant costs no model call. Stored results that don't match are never replaced: the board stops before it runs anything, lists each model with the reason, and says what to do (another `-o` for a quick check; move the model's folder to rerun it). `--no-resume` reruns every model and replaces their results ([#127](https://github.com/sandtable-ai/sandtable/issues/127), [#140](https://github.com/sandtable-ai/sandtable/issues/140), [#158](https://github.com/sandtable-ai/sandtable/issues/158), [#202](https://github.com/sandtable-ai/sandtable/issues/202)).
  - **Crashes.** A model, or the do-nothing baseline, whose trials crashed shows as an error row instead of a score. A crashed run never replaces stored results: it goes to a `crashed/` folder beside them, which the model's next good run removes ([#188](https://github.com/sandtable-ai/sandtable/issues/188), [#192](https://github.com/sandtable-ai/sandtable/issues/192), [#193](https://github.com/sandtable-ai/sandtable/issues/193)).
  - **Provenance.** Each `run.json` records the sandtable version and commit (`dirty` for uncommitted changes), the provider when a Claude model or caller ran, the AWS region when anything ran on Bedrock, and a Claude agent's effort. `leaderboard.json` records the sandtable that ranked the board and the `--prices` file, by path and sha256. A board that uses Bedrock without a region from `--region`, the environment or the AWS profile stops before it runs anything ([#152](https://github.com/sandtable-ai/sandtable/issues/152), [#158](https://github.com/sandtable-ai/sandtable/issues/158), [#159](https://github.com/sandtable-ai/sandtable/issues/159)).
  - **Effort.** A `claude:` entry can set `effort` (`low`, `medium`, `high`, `xhigh` or `max`), which the board shows next to the model's name; an `effort` on any other agent is an error ([#170](https://github.com/sandtable-ai/sandtable/issues/170), [#172](https://github.com/sandtable-ai/sandtable/issues/172)).
  - **Exit code.** The board exits 1 when every model failed or crashed (missing credentials, the wrong provider or region), after writing it, and points at each model's error. The do-nothing baseline doesn't count ([#217](https://github.com/sandtable-ai/sandtable/issues/217)).
  - `-m, --models` is required. Two labels that make the same folder name are refused before anything runs. `-t` limits every model and the baseline to some tasks, and a `noop` entry is skipped in favour of the built-in baseline ([#200](https://github.com/sandtable-ai/sandtable/issues/200), [#228](https://github.com/sandtable-ai/sandtable/issues/228)).
- **The freight leaderboard**: 13 models on `examples/freight`, 50 calls with 4 trials each. `leaderboard/models.yaml` holds the models, the caller, k, the rule that picked them and the models left out, and `prices/bedrock.eu-west-1.json` prices every one of them. [The leaderboard page](https://sandtable.dev/leaderboard) has the results, the method, how to reproduce it and its known limits. Every conversation is published in [sandtable-ai/leaderboard](https://github.com/sandtable-ai/leaderboard), and the README sums it up ([#47](https://github.com/sandtable-ai/sandtable/issues/47), [#150](https://github.com/sandtable-ai/sandtable/issues/150), [#168](https://github.com/sandtable-ai/sandtable/issues/168)).
- **Adapters**:
  - Claude on the Anthropic API or on Amazon Bedrock (`--provider bedrock`), with prompt caching. On a Bedrock geo profile (`eu.`, `us.`, `apac.`), Claude is priced at 1.1×, Anthropic's regional premium, and usage is recorded under the requested model ID ([#160](https://github.com/sandtable-ai/sandtable/issues/160))
  - any tool-capable model on Amazon Bedrock through the Converse API (`--agent bedrock:<model-id>`), with up to 16,000 output tokens per call and prompt caching on Claude and Nova models. Reasoning that a model writes into its text (`<reasoning>…</reasoning>`) is dropped before the caller and the graders see it ([#133](https://github.com/sandtable-ai/sandtable/issues/133), [#141](https://github.com/sandtable-ai/sandtable/issues/141), [#154](https://github.com/sandtable-ai/sandtable/issues/154))
  - any model behind an OpenAI-compatible Chat Completions endpoint (OpenAI, OpenRouter, LiteLLM, vLLM, Ollama, Groq, Together), as agent or simulated user: `--agent openai:<model>`, `--user openai:<model>`
  - the HTTP step protocol, keyed by a `session_id` of `<run-id>/<task-id>#<trial>` that no other run reuses; JS/TS module agents; the `noop` baseline; and a scripted caller
  - every tool call gets an answer. A call runs when its reply ended with `tool_use` or `end_turn`, and any other ending (cut off, filtered, refused, malformed) gets an error result. An empty reply or caller line never becomes an empty message that the API rejects ([#176](https://github.com/sandtable-ai/sandtable/issues/176))
  - retries with backoff on rate limits, server errors and network errors
  - setup errors say what to do: a missing `ANTHROPIC_API_KEY`, an unreachable HTTP agent (by URL), an unknown `--agent` (with the valid forms), or a missing optional package ([#96](https://github.com/sandtable-ai/sandtable/issues/96))
- **Costs**: built-in Claude prices, and `--prices <file>` for any other model. `scripts/bedrock-prices.mjs` writes that file from the AWS Pricing API. With `--verified`, it adds the models the Pricing API doesn't list from `prices/bedrock.verified.json`, where each price has its source, and it lists every model it can't price with the reason ([#137](https://github.com/sandtable-ai/sandtable/issues/137), [#148](https://github.com/sandtable-ai/sandtable/issues/148)).
- **Examples**:
  - `examples/freight`, a fictional freight carrier-sales desk with 50 tasks and 18 invariants, one of them soft. 32 tasks must write and 18 must not, and 18 form a `hard` tier: multi-load calls, corrections mid-call, negotiation across rounds, and identity and re-brokering traps. It covers vetting, search by lane, pickup window and equipment, negotiation under a ceiling with every counter-offer logged, offers a human rep confirms, capacity logging, callbacks and handoffs. Its policy states today's date and when a company name matches the carrier's MC record. `sandtable demo` rehearses it offline and opens the failing report ([#87](https://github.com/sandtable-ai/sandtable/issues/87), [#117](https://github.com/sandtable-ai/sandtable/issues/117), [#118](https://github.com/sandtable-ai/sandtable/issues/118), [#121](https://github.com/sandtable-ai/sandtable/issues/121), [#146](https://github.com/sandtable-ai/sandtable/issues/146), [#161](https://github.com/sandtable-ai/sandtable/issues/161), [#162](https://github.com/sandtable-ai/sandtable/issues/162), [#178](https://github.com/sandtable-ai/sandtable/issues/178))
  - `examples/clinic`, a fictional clinic front desk with 25 tasks and 12 invariants, and offline careful and naive agents (`--agent scripted:clinic-careful`)
  - worked examples for agents built with the Vercel AI SDK, the OpenAI Agents SDK, the Claude Agent SDK, Pipecat, LiveKit Agents and a plain HTTP service, each a one-file adapter checked offline in CI, with a guide ([#52](https://github.com/sandtable-ai/sandtable/issues/52))
- **Getting started**: the published CLI runs on Node.js 20 or later, with no engine warning. Under `npx sandtable-ai`, `examples/freight` and `examples/clinic` resolve to the copies bundled with the package from any directory. Every command in the docs, the CLI's hints and errors, and the files `init` drafts is `npx sandtable-ai …`, which runs as written however you installed it. npm and PyPI each have an unrelated package named `sandtable`, which a bare `npx sandtable` would download and run ([#99](https://github.com/sandtable-ai/sandtable/issues/99), [#101](https://github.com/sandtable-ai/sandtable/issues/101), [#129](https://github.com/sandtable-ai/sandtable/issues/129), [#215](https://github.com/sandtable-ai/sandtable/issues/215)).
- **Python launcher**: `uvx sandtable-ai` or `pip install sandtable-ai` gives a `sandtable` command that runs the matching CLI release (Node.js 20+ required). It hands signals to the CLI and starts from npm's cache without network ([#104](https://github.com/sandtable-ai/sandtable/issues/104)).
- **Claude Code plugin**: this repository is a plugin marketplace (`/plugin marketplace add sandtable-ai/sandtable`). Its skills teach a coding agent to draft and review a domain, write tasks, run it and attribute failures, and a `failure-triager` subagent reads failing trials. Not part of the npm package ([#72](https://github.com/sandtable-ai/sandtable/issues/72)).
- **Docs** at [sandtable.dev](https://sandtable.dev), with `llms.txt` for coding agents: concepts, guides, a reference for the CLI, the domain spec, the HTTP step protocol and `results.json`, and comparisons with τ-bench, LangWatch Scenario, IntellAgent and hosted platforms, each claim linked to the tool's own docs. The README's links and images are absolute, so they work on npmjs.com, and a test runs the quickstart's toy agent to keep its documented score true ([#54](https://github.com/sandtable-ai/sandtable/issues/54), [#103](https://github.com/sandtable-ai/sandtable/issues/103), [#216](https://github.com/sandtable-ai/sandtable/issues/216)).
