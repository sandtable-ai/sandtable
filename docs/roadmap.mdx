sandtable is in **beta**: the spec may still change before 1.0. [Issues](https://github.com/sandtable-ai/sandtable/issues) and [milestones](https://github.com/sandtable-ai/sandtable/milestones) on GitHub are the source of truth; this page mirrors [`ROADMAP.md`](https://github.com/sandtable-ai/sandtable/blob/main/ROADMAP.md).

## In 0.1.0, the first release

- Domain spec: world, tools (get/list/create/update/respond, checks, atomic ops, param defaults), invariants, personas, tasks
- Episode runner: simulated user ↔ agent, tool calls against a fresh world per trial
- Deterministic grading: end state, invariants on every tool call, `never_disclose` on agent messages, required and forbidden tools; pass^k; failure-mode clustering ([#24](https://github.com/sandtable-ai/sandtable/issues/24))
- Adapters: Claude as agent and simulated user on the Anthropic API or Amazon Bedrock, the Bedrock Converse adapter for non-Claude models, OpenAI-compatible endpoints, the HTTP step protocol, JS/TS module agents, a scripted user and the `noop` baseline ([#46](https://github.com/sandtable-ai/sandtable/issues/46), [#56](https://github.com/sandtable-ai/sandtable/issues/56), [#19](https://github.com/sandtable-ai/sandtable/issues/19))
- Reports: terminal, `results.json`, self-contained `report.html`, per-tag scores, token usage, estimated cost, turn latency; `--fail-under` CI gate
- `sandtable init`: OpenAPI → world tables and tools (deterministic), SOP → invariants that quote their source, transcripts → personas, tasks and fictional seed rows with PII scrubbed first ([#6](https://github.com/sandtable-ai/sandtable/issues/6), [#7](https://github.com/sandtable-ai/sandtable/issues/7), [#8](https://github.com/sandtable-ai/sandtable/issues/8))
- Review workflow: `review: pending`, `sandtable review`, `validate --strict`, provisional reports ([#9](https://github.com/sandtable-ai/sandtable/issues/9))
- `sandtable lint`: ready, solvable, non-vacuous, graded ([#10](https://github.com/sandtable-ai/sandtable/issues/10))
- `sandtable leaderboard`: several agents on one domain under the same simulated callers, next to a do-nothing baseline
- `sandtable regrade`: re-score stored trials after editing the domain's rules, without calling a model ([#32](https://github.com/sandtable-ai/sandtable/issues/32))
- Live verification of the Claude adapters, caching and init steps ([#1](https://github.com/sandtable-ai/sandtable/issues/1), [#3](https://github.com/sandtable-ai/sandtable/issues/3)); see [results](/results)
- Bundled examples with offline demo agents: a freight carrier-sales desk with negotiation rounds, rep-confirm offers, capacity and callbacks, and a clinic front desk ([#45](https://github.com/sandtable-ai/sandtable/issues/45), [#22](https://github.com/sandtable-ai/sandtable/issues/22))
- Worked examples for six agent frameworks ([#52](https://github.com/sandtable-ai/sandtable/issues/52))
- A Claude Code plugin whose skills and subagent let coding agents draft, run and debug suites ([#51](https://github.com/sandtable-ai/sandtable/issues/51))
- This docs site, with `llms.txt` ([#50](https://github.com/sandtable-ai/sandtable/issues/50))
- Packages on npm and PyPI, published from one tag ([#23](https://github.com/sandtable-ai/sandtable/issues/23))

## In 0.2.0

- Baseline comparison: `run --baseline` lists the tasks that broke, got worse, got fixed or changed since an earlier run ([#12](https://github.com/sandtable-ai/sandtable/issues/12), [#309](https://github.com/sandtable-ai/sandtable/issues/309))
- Reliability verdicts: pass@k, flaky tasks, flip rate and intervals; trials that end in an error are skipped, not failed ([#27](https://github.com/sandtable-ai/sandtable/issues/27))
- Critical tasks that fail the run whatever the score ([#28](https://github.com/sandtable-ai/sandtable/issues/28))
- Argument matchers in `called` and `not_called` ([#25](https://github.com/sandtable-ai/sandtable/issues/25)), per-task `given` rows and context ([#37](https://github.com/sandtable-ai/sandtable/issues/37)), `reference` calls the API rejects ([#274](https://github.com/sandtable-ai/sandtable/issues/274))
- Exit 1 for a failed gate and 2 for an error ([#282](https://github.com/sandtable-ai/sandtable/issues/282))
- `init`: drafts keep their sources' facts and quote every rule, drafted tasks carry reference calls, and each step prints its plan with `--dry-run` and what it cost ([#276](https://github.com/sandtable-ai/sandtable/issues/276), [#277](https://github.com/sandtable-ai/sandtable/issues/277), [#278](https://github.com/sandtable-ai/sandtable/issues/278), [#296](https://github.com/sandtable-ai/sandtable/issues/296), [#297](https://github.com/sandtable-ai/sandtable/issues/297))
- A simulated caller that says it doesn't know a fact its instructions leave out, instead of inventing one ([#287](https://github.com/sandtable-ai/sandtable/issues/287))
- The Claude Code plugin installs from the release tag ([#301](https://github.com/sandtable-ai/sandtable/issues/301)), and sandtable.dev documents the latest release ([#313](https://github.com/sandtable-ai/sandtable/issues/313))

## Next: 0.3.0, the last release before 1.0 (milestone v0.3)

0.3.0 is the last release that may change the contracts 1.0 freezes, so everything that could change them lands in it.

- Critical tasks and skipped trials in `leaderboard` and `demo --live` ([#284](https://github.com/sandtable-ai/sandtable/issues/284))
- Failure attribution: agent, simulated user, task or infrastructure ([#29](https://github.com/sandtable-ai/sandtable/issues/29))
- Nested params: objects and arrays in tool schemas ([#26](https://github.com/sandtable-ai/sandtable/issues/26))
- Readers of `results.json` check its version ([#349](https://github.com/sandtable-ai/sandtable/issues/349))
- Node 22 and Python 3.10 as the oldest supported versions ([#350](https://github.com/sandtable-ai/sandtable/issues/350))
- A last review of every contract before it freezes ([#351](https://github.com/sandtable-ai/sandtable/issues/351))
- A regression gate ([#281](https://github.com/sandtable-ai/sandtable/issues/281)), comparing two stored runs ([#285](https://github.com/sandtable-ai/sandtable/issues/285)), per-tag pass^k floors ([#283](https://github.com/sandtable-ai/sandtable/issues/283))

## 1.0: stable contracts (milestone v1.0)

1.0 promises that the domain spec, `results.json`, CLI commands, flags and exit codes, the HTTP step protocol and the library's exports change only in a major release.

- A stability policy: what is covered, semver, and the deprecation window ([#352](https://github.com/sandtable-ai/sandtable/issues/352))
- A release candidate, tested end to end before 1.0.0 ([#353](https://github.com/sandtable-ai/sandtable/issues/353))

## After 1.0 (milestones v1.1 and black-box)

- PR comments with pass^k deltas ([#13](https://github.com/sandtable-ai/sandtable/issues/13)), coverage matrix ([#30](https://github.com/sandtable-ai/sandtable/issues/30)), customer sign-off report: rule → evidence → reliability ([#31](https://github.com/sandtable-ai/sandtable/issues/31))
- Black-box and platform on-ramps: serve the world as REST, MCP and webhook tools for hosted agent platforms ([#14](https://github.com/sandtable-ai/sandtable/issues/14)), import voice-agent platform configs as draft domains ([#34](https://github.com/sandtable-ai/sandtable/issues/34), [#35](https://github.com/sandtable-ai/sandtable/issues/35)), fault profiles ([#15](https://github.com/sandtable-ai/sandtable/issues/15))

## Contribute

Good first issues: `$regex` in where clauses ([#20](https://github.com/sandtable-ai/sandtable/issues/20)) and a `--tag` filter ([#21](https://github.com/sandtable-ai/sandtable/issues/21)). Example domains and adapters are welcome too; see [`CONTRIBUTING.md`](https://github.com/sandtable-ai/sandtable/blob/main/CONTRIBUTING.md). Example domains must be fictional: no real company names, customer data or proprietary procedures.
