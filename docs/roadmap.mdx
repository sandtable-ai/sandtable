sandtable is stable since 1.0: the contracts change only in a major release, as the [stability policy](/reference/stability) says. [Issues](https://github.com/sandtable-ai/sandtable/issues) and [milestones](https://github.com/sandtable-ai/sandtable/milestones) on GitHub are the source of truth; this page mirrors [`ROADMAP.md`](https://github.com/sandtable-ai/sandtable/blob/main/ROADMAP.md).

## In 0.1.0, the first release

- Domain spec: world, tools (get/list/create/update/respond, checks, atomic ops, param defaults), invariants, personas, tasks
- Episode runner: simulated user ↔ agent, tool calls against a fresh world per trial
- Deterministic grading: end state, invariants on every tool call, `never_disclose` on agent messages, required and forbidden tools; pass^k; failure-mode clustering ([#24](https://github.com/sandtable-ai/sandtable/issues/24))
- Adapters: Claude as agent and simulated user on the Anthropic API or Amazon Bedrock, the Bedrock Converse adapter for non-Claude models, OpenAI-compatible endpoints, the HTTP step protocol, JS/TS module agents, a scripted user and the `noop` baseline ([#46](https://github.com/sandtable-ai/sandtable/issues/46), [#56](https://github.com/sandtable-ai/sandtable/issues/56), [#19](https://github.com/sandtable-ai/sandtable/issues/19))
- Reports: terminal, `results.json`, self-contained `report.html`, per-tag scores, token usage, estimated cost, turn latency; `--fail-under` CI gate
- `sandtable init`: OpenAPI → world tables and tools (deterministic), SOP → invariants that quote their source, transcripts → personas, tasks and fictional seed rows with PII scrubbed first ([#6](https://github.com/sandtable-ai/sandtable/issues/6), [#7](https://github.com/sandtable-ai/sandtable/issues/7), [#8](https://github.com/sandtable-ai/sandtable/issues/8))
- Review workflow: `review: pending`, `sandtable review`, `validate --strict`, provisional reports ([#9](https://github.com/sandtable-ai/sandtable/issues/9))
- `sandtable lint`: ready, solvable, non-vacuous, graded ([#10](https://github.com/sandtable-ai/sandtable/issues/10))
- `sandtable leaderboard`: several agents on one domain under the same simulated callers, next to a do-nothing baseline
- `sandtable regrade`: re-score stored trials after editing the domain's rules, without calling a model ([#32](https://github.com/sandtable-ai/sandtable/issues/32))
- Live verification of the Claude adapters, caching and init steps ([#1](https://github.com/sandtable-ai/sandtable/issues/1), [#3](https://github.com/sandtable-ai/sandtable/issues/3)); see [results](/results)
- Bundled examples with offline demo agents: a freight carrier-sales desk with negotiation rounds, rep-confirm offers, capacity and callbacks, and a clinic front desk ([#45](https://github.com/sandtable-ai/sandtable/issues/45), [#22](https://github.com/sandtable-ai/sandtable/issues/22))
- Worked examples for six agent frameworks ([#52](https://github.com/sandtable-ai/sandtable/issues/52))
- A Claude Code plugin whose skills and subagent let coding agents draft, run and debug suites ([#51](https://github.com/sandtable-ai/sandtable/issues/51))
- This docs site, with `llms.txt` ([#50](https://github.com/sandtable-ai/sandtable/issues/50))
- Packages on npm and PyPI, published from one tag ([#23](https://github.com/sandtable-ai/sandtable/issues/23))

## In 0.2.0

- Baseline comparison: `run --baseline` lists the tasks that broke, got worse, got fixed or changed since an earlier run ([#12](https://github.com/sandtable-ai/sandtable/issues/12), [#309](https://github.com/sandtable-ai/sandtable/issues/309))
- Reliability verdicts: pass@k, flaky tasks, flip rate and intervals; trials that end in an error are skipped, not failed ([#27](https://github.com/sandtable-ai/sandtable/issues/27))
- Critical tasks that fail the run whatever the score ([#28](https://github.com/sandtable-ai/sandtable/issues/28))
- Argument matchers in `called` and `not_called` ([#25](https://github.com/sandtable-ai/sandtable/issues/25)), per-task `given` rows and context ([#37](https://github.com/sandtable-ai/sandtable/issues/37)), `reference` calls the API rejects ([#274](https://github.com/sandtable-ai/sandtable/issues/274))
- Exit 1 for a failed gate and 2 for an error ([#282](https://github.com/sandtable-ai/sandtable/issues/282))
- `init`: drafts keep their sources' facts and quote every rule, drafted tasks carry reference calls, and each step prints its plan with `--dry-run` and what it cost ([#276](https://github.com/sandtable-ai/sandtable/issues/276), [#277](https://github.com/sandtable-ai/sandtable/issues/277), [#278](https://github.com/sandtable-ai/sandtable/issues/278), [#296](https://github.com/sandtable-ai/sandtable/issues/296), [#297](https://github.com/sandtable-ai/sandtable/issues/297))
- A simulated caller that says it doesn't know a fact its instructions leave out, instead of inventing one ([#287](https://github.com/sandtable-ai/sandtable/issues/287))
- The Claude Code plugin installs from the release tag ([#301](https://github.com/sandtable-ai/sandtable/issues/301)), and sandtable.dev documents the latest release ([#313](https://github.com/sandtable-ai/sandtable/issues/313))

## In 0.3.0

- Regression gates: `run --fail-on-regression` ([#281](https://github.com/sandtable-ai/sandtable/issues/281)), `sandtable compare` for two stored runs ([#285](https://github.com/sandtable-ai/sandtable/issues/285)), per-tag pass^k floors with `--floor` ([#283](https://github.com/sandtable-ai/sandtable/issues/283))
- `leaderboard` and `demo --live` treat critical tasks and skipped trials as `run` does ([#284](https://github.com/sandtable-ai/sandtable/issues/284))
- Failure attribution: each trial that didn't pass names a likely owner, agent, simulated user, task spec or harness, from deterministic evidence ([#29](https://github.com/sandtable-ai/sandtable/issues/29), [#385](https://github.com/sandtable-ai/sandtable/issues/385))
- Nested params: objects, arrays and nullable fields in tool schemas, `$contains` and dotted fields in where clauses, and `init --openapi` mapping nested bodies ([#26](https://github.com/sandtable-ai/sandtable/issues/26))
- Contracts readied for 1.0: `results.json` readers check its version and it records the sandtable-ai that wrote it ([#349](https://github.com/sandtable-ai/sandtable/issues/349), [#372](https://github.com/sandtable-ai/sandtable/issues/372)), the library exports only its documented API ([#370](https://github.com/sandtable-ai/sandtable/issues/370)), reference pages kept in step with the code by tests ([#371](https://github.com/sandtable-ai/sandtable/issues/371)), and a stability policy ([#352](https://github.com/sandtable-ai/sandtable/issues/352))
- Node.js 22 and Python 3.10 as the oldest supported versions ([#350](https://github.com/sandtable-ai/sandtable/issues/350))
- Freight example fixes: callers that know their truck's availability and don't repeat the agent's numbers ([#346](https://github.com/sandtable-ai/sandtable/issues/346), [#383](https://github.com/sandtable-ai/sandtable/issues/383)), and a made-up load ID filed under its own rule ([#163](https://github.com/sandtable-ai/sandtable/issues/163))

## In 1.0

- Stable contracts: the domain spec, `results.json`, CLI commands, flags and exit codes, the HTTP step protocol and the library's exports change only in a major release, as the [stability policy](/reference/stability) says ([#352](https://github.com/sandtable-ai/sandtable/issues/352), [#394](https://github.com/sandtable-ai/sandtable/issues/394))
- A release candidate, `1.0.0-rc.1`, tested end to end before 1.0.0 ([#353](https://github.com/sandtable-ai/sandtable/issues/353))
- `init --transcripts` flags names, usernames, emails, phone numbers and street addresses a draft copied from its chats, and `sandtable review` shows each item's notes ([#388](https://github.com/sandtable-ai/sandtable/issues/388))
- The drafting skill writes the plan of a paid `init` as its own message, and waits for a go-ahead unless model steps are authorized ([#392](https://github.com/sandtable-ai/sandtable/issues/392))

## In 1.1

- Coverage: `run` shows which rules its trials checked and which they caught broken, and `lint` says which rules the tasks put in play ([#30](https://github.com/sandtable-ai/sandtable/issues/30))
- A [customer sign-off report](/guides/customer-signoff), `report --audience customer`: each rule with its source, the scenarios that checked it and the open items, with `run --without-policy` as a careless agent that shows the scenarios can catch a mistake ([#31](https://github.com/sandtable-ai/sandtable/issues/31), [#405](https://github.com/sandtable-ai/sandtable/issues/405))
- `run --tag` runs only the tasks with those tags ([#21](https://github.com/sandtable-ai/sandtable/issues/21)), and a repeated `--tasks` adds its tasks ([#403](https://github.com/sandtable-ai/sandtable/issues/403))
- The Claude Code plugin keeps `npm install` of sandtable in the working folder's own project ([#412](https://github.com/sandtable-ai/sandtable/issues/412))

## In 1.2

- [Agents that call their own tools](/guides/black-box): `run --serve` serves each trial's world over REST, MCP and webhooks while sandtable drives the conversation, and `sandtable serve` grades the conversations a hosted voice platform's own test calls drive ([#14](https://github.com/sandtable-ai/sandtable/issues/14), [#443](https://github.com/sandtable-ai/sandtable/issues/443), [#444](https://github.com/sandtable-ai/sandtable/issues/444))
- [Faults and events](/reference/spec#faults-and-events): a task's tool calls can time out, hit a rate limit or a server error, or time out after their write landed, and the world can change mid-call; the freight example catches an agent that books twice after a timeout ([#15](https://github.com/sandtable-ai/sandtable/issues/15))
- `sandtable import vapi` drafts a domain from a Vapi assistant's export and its simulation scenarios ([#34](https://github.com/sandtable-ai/sandtable/issues/34))
- The Claude Code plugin's hooks cover `npm run sandtable` from a subfolder and with npm's options, and stop the unrelated npm package named `sandtable` from being installed in sandtable's place ([#430](https://github.com/sandtable-ai/sandtable/issues/430), [#439](https://github.com/sandtable-ai/sandtable/issues/439), [#441](https://github.com/sandtable-ai/sandtable/issues/441))
