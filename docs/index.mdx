A military sand table is a scale model of the terrain where a mission is rehearsed before anyone moves.

**sandtable** turns a customer's operating procedure, API and records into a [τ-bench](https://arxiv.org/abs/2406.12045)-style simulation. Simulated customers call your agent. Its tool calls hit stateful mocks of the customer's systems. Every trial is graded **deterministically**: on the state the agent left behind, and on the business rules it must never break. You get **pass^k** (does it succeed *every* time?), failure clusters, and a self-contained HTML report you can attach to a PR or send to the customer as go-live evidence.

<Warning>
sandtable is in **beta**. The simulation engine, graders, adapters and reports work and are tested, and the Claude adapters and `init`'s model-backed steps have been verified in [live runs](/results). The OpenAI-compatible and Bedrock Converse adapters are newer. The spec may still change before 1.0. See the [roadmap](/roadmap).
</Warning>

## Why

Agents that pass a demo fail on the seventh customer, because each customer has its own rules, systems and edge cases. The usual test setups miss this:

- **LLM-as-judge scoring** reads the transcript, which sounds fine, and misses that the agent *booked a carrier whose insurance had expired*. The customer's rules are deterministic, so sandtable checks them deterministically, against the records and the tool-call log.
- **Success rate hides unreliability.** An agent that is right 80% of the time fails one call in five in production. sandtable runs each task *k* times and reports pass^k, the probability that all *k* trials succeed.
- **Benchmarks don't know your customer.** Public benchmark domains are useful for comparing models, but you need a benchmark of *this* customer's workflow, kept in their repo and run on every prompt or model change.

## Who it is for

Engineers who deploy agents into customers' workflows and need evidence that the agent follows *that* customer's rules: before go-live, and again after every prompt, model or tool change. It works with agents built on any stack, as long as they can be called over HTTP or wrapped in a small JavaScript or TypeScript module. It can also run Claude, models on Amazon Bedrock, or any model behind an OpenAI-compatible endpoint with the same prompt and tools, so you can compare models on the customer's own workflow.

If you work in Claude Code, the [sandtable plugin](/guides/claude-code-plugin) lets your coding agent draft, lint and run a domain for you, and triage the failures.
